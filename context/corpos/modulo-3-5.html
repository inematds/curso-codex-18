🧳 A pasta .agents e a vinda do Claude Code

As skills moram numa pasta chamada .agents, no projeto ou no seu usuário. Entender esse endereço permite organizar sua biblioteca de receitas e trazer para o Codex um projeto que você montou em outro agente, como o Claude Code.

1

Encontre a pasta .agents

No módulo anterior, a skill da Paula foi salva em .agents/skills/descricao-post/SKILL.md. Esse caminho tem lógica: a pasta .agents guarda as skills, e dentro dela cada skill tem a sua própria pasta.

É o mesmo desenho da pasta .codex que você viu na Trilha 2: .codex guarda configurações, .agents guarda receitas. As duas começam com ponto, e é por isso que às vezes "somem" da vista.

🆕 Novo aqui? Pasta com ponto e "raiz"

  • Pasta oculta — pasta cujo nome começa com ponto (.agents). O sistema esconde por padrão. No Mac, aperte Command + Shift + ponto no Finder; no Windows, ative "Itens ocultos" no menu Exibir do Explorador.
  • Raiz do projeto — o primeiro nível da pasta do projeto, onde ficam o AGENTS.md e as pastas .agents e .codex.
  • Usuário — a sua pasta pessoal no computador (o símbolo ~ é o atalho para ela).

Como ler o desenho: o bloco roxo é a pasta .agents. Repare no padrão: uma pasta por skill, e dentro de cada uma o mesmo arquivo SKILL.md. O olho riscado lembra por que você talvez não a veja de primeira.

💡 Não achou? Peça ao Codex

Pergunte "liste as pastas que começam com ponto neste projeto e o que há dentro de .agents". Ele mostra o caminho completo, sem você mexer nas opções do sistema.

2

Separe skills do projeto e skills globais

Existem dois endereços para skills. Dentro do projeto (.agents/skills/), a skill só vale ali. Na sua pasta de usuário (~/.agents/skills/), ela vale em todos os projetos: é uma skill global.

A pergunta que decide é simples: "eu usaria esta receita em outro projeto?". A skill de promoção da loja é do loja-rui. Já uma skill que revisa ortografia e deixa o texto mais claro serve para qualquer coisa que o Rui escreva: vai para o usuário.

Como ler o desenho: o bloco azul de cima é o usuário, e as linhas tracejadas mostram que as skills dele chegam a todos os projetos. Os blocos roxos de baixo são as skills de cada projeto, que não "vazam" para o vizinho.

✓ No projeto

  • ✓ Usa arquivos daquele projeto (estoque, clientes)
  • ✓ Tem regras de um negócio específico
  • ✓ Vai junto se você mandar a pasta para alguém
  • ✓ Ex.: promocao-semana, proposta-cliente

✓ No usuário (global)

  • ✓ Serve para qualquer trabalho seu
  • ✓ Não depende de arquivo de um projeto
  • ✓ Reflete o seu jeito pessoal, não o de um cliente
  • ✓ Ex.: revisar-texto, resumo-reuniao

✗ Sinais de skill no lugar errado

  • ✗ Skill global que cita "a planilha de estoque": em outro projeto, essa planilha não existe
  • ✗ A mesma skill copiada em cinco projetos: ela deveria ser global
  • ✗ Duas skills com o mesmo nome, uma global e outra no projeto, fazendo coisas diferentes
3

Faça a skill usar outros arquivos

Uma skill não precisa carregar tudo dentro do SKILL.md. Ela pode apontar para outros arquivos: um guia de voz, um modelo de proposta, uma planilha, até outra skill. O Codex abre esses arquivos só quando a receita manda.

Isso deixa a receita curta e fácil de manter. Quando a Paula muda o modelo de proposta, ela edita um arquivo só, e a skill passa a usar a versão nova sem ninguém tocar nela.

Como ler o desenho: o centro roxo é a receita, curta. Os quatro cantos são materiais que ela consulta. Mudar um canto não exige reescrever o centro, e o mesmo guia de voz pode servir a várias skills.

📄 Copia e cola: skill que aponta para outros arquivos

Objetivo: uma skill curta que usa materiais guardados em outros arquivos do projeto. Salve em .agents/skills/proposta-cliente/SKILL.md.

---
name: proposta-cliente
description: Use quando eu pedir uma proposta comercial para um cliente de consultoria de RH. Monta a proposta no meu modelo e no meu tom.
---

# Antes de escrever, leia
- O tom de voz em linkedin/guia-de-voz.md
- A estrutura em modelos/modelo-proposta.md
- Os valores em propostas/precos.csv (nunca invente preço)

# Passos
1. Leia a ficha do cliente em clientes/.
2. Preencha o modelo com o problema e a solução do cliente.
3. Use só valores da tabela de preços.
4. Salve em propostas/ com a data no começo do nome.
Como verificar: peça uma proposta e, no fim, pergunte "quais arquivos você abriu para fazer isso?". A resposta tem de citar os três arquivos da seção "Antes de escrever, leia".
4

Traga seu projeto do Claude Code

Muita gente começa em outro agente, como o Claude Code, e depois quer usar o Codex também. A boa notícia: as ideias são as mesmas, só mudam os nomes dos arquivos. Lá existe o CLAUDE.md e a pasta .claude; aqui, o AGENTS.md e as pastas .agents e .codex.

A mudança é como uma mala: você leva as regras, as receitas e as configurações. E o jeito mais simples de fazer a mala é pedir ao próprio Codex: "analise este projeto, que eu montei no Claude Code, e deixe-o pronto para o Codex".

Como ler o desenho: cada caixa amarela da esquerda tem um par roxo à direita, na mesma altura. Regras viram regras, receitas viram receitas, configurações viram configurações. A mala do meio é o pedido que você faz ao Codex.

1

Faça uma cópia de segurança

Antes de tudo, copie a pasta do projeto para outro lugar, ou use uma worktree (módulo 2.2). Se algo sair errado, o original está intacto.

2

Abra a pasta no Codex

Pelo aplicativo ou com codex dentro da pasta. Ele enxerga os arquivos do Claude Code como enxerga qualquer outro arquivo.

3

Peça o plano de migração

Use o pedido do quadro abaixo. Ele lista o que vai copiar, adaptar ou deixar como está, e espera o seu "pode fazer".

4

Teste uma tarefa de sempre

Peça algo que você fazia toda semana no outro agente. Se sair no mesmo padrão, a mudança deu certo.

💬 Copia e cola no Codex: a mudança do Claude Code

Objetivo: deixar pronto para o Codex um projeto montado no Claude Code, sem perder nada do que já funciona.

Este projeto foi montado no Claude Code. Analise o CLAUDE.md, a pasta .claude e o resto da estrutura e deixe tudo pronto para o Codex: crie o AGENTS.md com as mesmas regras (mantenha o CLAUDE.md, os dois podem conviver), copie as skills para .agents/skills/ e me diga quais configurações precisam ser adaptadas para .codex. Primeiro me mostre o plano em forma de lista. Não apague nada.
Como verificar: depois de aplicar, o projeto tem AGENTS.md e CLAUDE.md lado a lado, e a pasta .agents/skills/ tem o mesmo número de skills que havia antes. Pergunte "que skills você tem disponíveis neste projeto?" e confira a lista.
5

Mantenha um projeto que serve a qualquer agente

Repare no que a mudança mostrou: o valor do projeto não estava na ferramenta, estava nos arquivos. Regras, receitas, modelos, histórico. Tudo em texto simples, numa pasta sua.

Isso é liberdade. Se amanhã surgir um agente melhor, a Paula abre a mesma pasta nele e continua de onde parou. Ferramentas vêm e vão; a pasta bem organizada fica.

Como ler o desenho: a pasta roxa é o centro fixo. Os agentes giram em volta e se ligam a ela. O círculo pontilhado de baixo é o agente que ainda nem existe: quando chegar, ele também vai ler a mesma pasta.

✓ Projeto que viaja bem

  • ✓ Regras em arquivo de texto na raiz
  • ✓ Skills em pastas, uma por receita
  • ✓ Modelos e exemplos como arquivos, não só na conversa
  • ✓ Decisões importantes anotadas num arquivo

✗ Projeto preso a uma ferramenta

  • ✗ Regras só ditas na conversa, nunca salvas
  • ✗ O "jeito certo" mora só na sua cabeça
  • ✗ Duas versões das regras que se contradizem
  • ✗ Tudo depende de um recurso que só um app tem

💡 Uma fonte só para as regras

Se você mantém CLAUDE.md e AGENTS.md juntos, escolha um deles como o principal e peça ao agente para manter o outro igual. Duas versões que divergem viram dois agentes com regras diferentes no mesmo projeto.

6

Organize sua biblioteca de skills

Depois de alguns meses, o Rui tinha 23 skills. Algumas ótimas, outras esquecidas, duas fazendo quase a mesma coisa. O Codex começou a escolher a receita errada de vez em quando.

Biblioteca de skills é como a prateleira de temperos: rende quando está etiquetada, sem repetição e sem vidro vazio. Uma faxina a cada mês resolve.

Como ler o desenho: em cima, nomes que não dizem nada, receitas repetidas e uma vazia confundem o Codex. Embaixo, menos potes, todos com nome claro; os roxos são do projeto e os azuis são globais.

HábitoPor quêExemplo
Nome que diz o que fazVocê e o Codex entendem sem abrirpromocao-semana, não promo2
Uma pasta por skillCada receita com seus arquivos de apoio.agents/skills/promocao-semana/
Juntar as parecidasEvita que ele escolha a erradapromo + promo2 viram uma só
Apagar as que não usaMenos ruído na hora de escolhera de teste do primeiro dia

O que olhar na tabela: o terceiro hábito é o que mais melhora as escolhas do Codex. Duas skills parecidas fazem ele hesitar.

💬 Copia e cola no Codex: a faxina do mês

Objetivo: receber um diagnóstico da sua biblioteca antes de mexer em qualquer skill.

Liste todas as skills deste projeto e as globais do meu usuário. Para cada uma, diga: o que faz, se o nome é claro, se há outra parecida e se deveria estar no projeto ou no usuário. Termine com uma proposta de faxina (juntar, renomear, mover, apagar). Não altere nada até eu aprovar.
Como verificar: a lista tem de bater com as pastas que você vê em .agents/skills/ e em ~/.agents/skills/. Nenhuma pasta muda até você responder "pode aplicar".

Teste rápido (opcional): o Rui quer uma skill de revisão de texto que sirva para tudo o que ele escreve, em qualquer projeto. Onde ela deve ficar?
