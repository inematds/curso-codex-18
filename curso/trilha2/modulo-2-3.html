⚙️ A pasta .codex: configurações

As preferências do Codex moram em pastas chamadas .codex: uma dentro do projeto e outra na sua pasta de usuário. Entender a diferença entre as duas é a ideia mais útil deste módulo, e ela volta quando chegarmos às skills.

1

Encontre a pasta .codex

A Paula abriu a pasta paula-escritorio no explorador de arquivos e não viu nenhum .codex. Não é que ele não exista: está escondido. Toda pasta cujo nome começa com ponto é oculta.

O ponto é uma convenção antiga: "isto é configuração, não mexa sem querer". Para ver, é só pedir ao sistema que mostre os itens ocultos. Nada muda nos arquivos; eles só aparecem.

🆕 Novo aqui? Quatro palavras deste módulo

  • Pasta oculta — pasta com ponto no começo do nome. Existe, mas o sistema esconde por padrão.
  • Configuração — uma preferência guardada em arquivo: qual modelo usar, quanto esforço, o que pode ou não fazer.
  • Pasta de usuário — a sua pasta pessoal no computador. No terminal ela tem o apelido ~. Então ~/.codex é "a pasta .codex dentro da minha pasta pessoal".
  • config.toml — o arquivo de texto com as configurações do Codex, no formato chave = valor.

Como ler o desenho: é a mesma pasta nas duas janelas. Só muda o olho no canto: fechado, a .codex some; aberto, ela aparece (meio transparente, como os sistemas costumam mostrar itens ocultos).

SistemaComo mostrar itens ocultos
WindowsNo Explorador de Arquivos, menu Exibir → Mostrar → Itens ocultos
MacNo Finder, atalho Cmd + Shift + ponto
LinuxNo gerenciador de arquivos, atalho Ctrl + H

O que olhar na tabela: o atalho do seu sistema. Os nomes dos menus mudam um pouco entre versões, mas a opção sempre fala em "ocultos". O mesmo atalho esconde de novo.

2

Separe projeto de usuário

Existem dois lugares para a .codex. No projeto (paula-escritorio/.codex/): configurações que valem só para aquele projeto, como agentes e fluxos próprios dele.

No usuário (~/.codex/): configurações globais, que valem para todos os projetos daquele computador. É como a diferença entre a regra de uma sala e a regra do prédio inteiro.

Como ler o desenho: o guarda-chuva azul é a configuração de usuário: cobre os três projetos. A caixinha ciano dentro do projeto da Paula vale só ali. Os projetos sem caixinha ficam apenas com o que vem do guarda-chuva.

✓ Vai no .codex do projeto

  • ✓ O que só faz sentido para aquele trabalho
  • ✓ Agentes e fluxos próprios do projeto
  • ✓ Ajustes que você quer levar junto com a pasta

✓ Vai no ~/.codex do usuário

  • ✓ Seu modelo e esforço padrão
  • ✓ O que vale para qualquer projeto seu
  • ✓ Login, histórico e memórias (o Codex cuida sozinho)

💡 Guarde esta pergunta: "projeto ou usuário?"

Ela volta no módulo 3.5, com a pasta .agents das skills: skill do projeto vale só ali; skill do usuário vale em todo lugar. Quem entende aqui, entende lá.

3

Leia o config.toml sem medo

O coração da configuração é o config.toml. O nome assusta, mas por dentro é uma lista de preferências, uma por linha: o nome da preferência, um sinal de igual e o valor escolhido.

O Rui abriu o dele num editor de texto comum e encontrou duas linhas. Em cinco minutos entendeu tudo: qual modelo ele usa por padrão e quanto esse modelo pensa.

Como ler o desenho: cada linha tem três partes. A seta da esquerda aponta a chave, a de cima o sinal de igual e a da direita o valor. Mudar a configuração é trocar o valor, nunca o nome da chave.

📄 Copia e cola: um config.toml mínimo

Objetivo: reconhecer as duas preferências mais comuns e o que cada uma faz.

model = "gpt-6-astra"
model_reasoning_effort = "medium"

A primeira linha escolhe o modelo padrão. A segunda diz quanto ele pensa antes de responder. Os modelos e os níveis de esforço são assunto dos módulos 3.1 e 3.2.

Como verificar: abra uma conversa nova e olhe o seletor embaixo da caixa de mensagem. O modelo e o esforço mostrados devem ser os mesmos do arquivo. Se algo parecer errado, codex doctor faz um diagnóstico da instalação.

🆕 Novo aqui? TOML e aspas

TOML é só o nome do formato do arquivo, feito para ser lido por gente. Texto vai entre aspas ("medium"). Esquecer uma aspa é o erro mais comum de quem edita à mão, e é por isso que o próximo tópico manda pedir ao Codex.

4

Saiba o que fica na pasta global

A ~/.codex é a gaveta pessoal do Codex no seu computador. Além do config.toml, ele guarda ali as memórias, o histórico das sessões, as automações e o seu login.

Quase tudo isso o próprio Codex escreve e lê. Você não precisa abrir, mas precisa saber que existe, porque essa pasta tem a sua conta dentro. Os nomes exatos dos arquivos internos podem mudar entre versões.

Como ler o desenho: cada gaveta guarda um tipo de coisa. As notas à direita dizem quem mexe: a de cima é sua, as do meio são do Codex e a de baixo, em vermelho, é a chave da sua conta.

GavetaPara que serveVocê mexe?
config.tomlModelo, esforço e outras preferênciasSim, de preferência pedindo ao Codex
MemóriasFatos que ele lembra sobre vocêPeça para revisar ou apagar uma memória
Histórico de sessõesPermite retomar com codex resumeNão
AutomaçõesTarefas que rodam sozinhas (módulo 4.4)Pelo app, não pelo arquivo
LoginMantém você conectado (codex login)Nunca. E nunca envie a ninguém

O que olhar na tabela: a coluna da direita. Só a primeira linha é "sua" no dia a dia; o resto existe para o Codex funcionar.

5

Peça ao Codex para ajustar a configuração

Você quase não precisa editar nada à mão. O Codex sabe onde ficam os arquivos e consulta a própria documentação para escrever a configuração certa. Diga o que quer em português.

A Paula pediu: "deixe o esforço padrão em medium neste projeto". Antes, perguntou: "isso vai no .codex do projeto ou no global?". Essa segunda pergunta é a que evita surpresa em outro projeto.

Como ler o desenho: siga os números no sentido horário, a partir do topo. O arquivo no centro só muda no passo 5, depois que você viu a linha nova. Os passos 3 e 4 são a sua rede de segurança.

1

Diga o que quer, não como fazer

"Quero que, neste projeto, ele pense mais antes de responder." Não precisa saber o nome da chave.

2

Pergunte onde vai

Projeto (só aqui) ou usuário (todos os projetos)? Escolha de propósito.

3

Peça para ver antes de gravar

Ele mostra o arquivo e a linha nova. Você aprova.

4

Teste numa conversa nova

Configurações costumam valer a partir da próxima conversa. Abra uma e confira o seletor.

💬 Copia e cola no Codex: ajustar sem editar à mão

Objetivo: mudar uma preferência no lugar certo, vendo a mudança antes.

Quero que o esforço padrão seja medium só neste projeto, sem mudar os outros. Consulte a sua documentação, me diga em que arquivo isso fica (no .codex do projeto ou no global) e me mostre a linha exata que vai escrever. Só grave depois que eu aprovar.
Como verificar: abra uma conversa nova neste projeto e confira o esforço no seletor. Depois abra uma conversa em outro projeto: lá o esforço deve continuar como estava.

💡 Para uma sessão só, nem precisa de arquivo

Se a mudança é só para hoje, troque no seletor do app ou abra o terminal com codex -c model_reasoning_effort="high". Quando fechar, volta ao padrão do config.toml.

6

Proteja o que não deve sair da máquina

O Rui quis ajudar um amigo e pensou em mandar a pasta ~/.codex inteira, "com a configuração pronta". Ainda bem que perguntou antes. Ali dentro está o login dele (auth.json), o histórico de conversas e as memórias sobre a loja.

Quem recebe essa pasta pode entrar na conta dele e ler o que ele conversou. A regra é simples: a pasta global não sai do seu computador. Para ajudar alguém, mande só as linhas do config.toml que interessam.

Como ler o desenho: o escudo é o seu computador protegendo a pasta global. A seta vermelha de cima (a pasta inteira saindo) está bloqueada. A seta verde de baixo é o jeito certo: copiar só as linhas de configuração, sem nada pessoal.

✗ Nunca

  • ✗ Enviar a pasta ~/.codex para alguém
  • ✗ Colar o conteúdo do auth.json num chat ou e-mail
  • ✗ Pôr a pasta global numa pasta compartilhada da nuvem
  • ✗ Escrever senha ou chave dentro do config.toml ou do AGENTS.md

✓ Sempre

  • ✓ Compartilhar só linhas de preferência, copiadas à mão
  • ✓ Revisar o .codex do projeto antes de mandar a pasta do projeto
  • ✓ Se o login vazar, troque a senha da conta e entre de novo com codex login
  • ✓ Perguntar ao Codex "tem algo pessoal nesta pasta?" antes de enviar

Teste rápido (opcional): o Rui quer passar a configuração dele para um amigo. O que ele deve enviar?
