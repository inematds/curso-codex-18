🌐 Navegador: o Codex usa sites por você

Nem todo site tem plugin ou integração. Para esses, o Codex abre um navegador próprio, olha a tela, clica e digita como você faria. Você faz o login uma vez e ele reaproveita a sessão.

1

Conheça o navegador dentro do Codex

Até aqui o Codex trabalhou com arquivos da sua pasta e com aplicativos conectados por plugin. Mas boa parte da vida acontece em sites: o portal do fornecedor, a área do cliente do banco, a comunidade onde você posta, o painel da prefeitura.

Para isso o aplicativo tem um navegador embutido: uma aba de internet que fica dentro do próprio Codex. O agente abre essa aba, lê a página, clica nos botões e preenche campos. Você acompanha tudo ao vivo. O nome do botão pode mudar entre versões; procure por "navegador" ou pelo ícone de globo.

🆕 Novo aqui? Quatro palavras deste módulo

  • Navegador embutido — uma janela de internet que mora dentro do aplicativo do Codex, separada do seu Chrome ou Safari.
  • Sessão — o "estou logado" que o site lembra depois que você entra com usuário e senha.
  • Integração — uma porta oficial que o site oferece para outros programas conversarem com ele (plugin, API ou MCP).
  • Visão — a capacidade do modelo de olhar uma imagem da tela e entender o que há nela: botões, campos, textos.

Como ler o desenho: o pedido é escrito na conversa (meio), mas a ação acontece na aba do navegador (direita). O cursor azul é o agente, não você. Ele lê a lista de pedidos e vai até o botão certo.

✗ Sem o navegador

  • ✗ Você entra no site e copia os dados à mão
  • ✗ Cola na conversa para o Codex trabalhar
  • ✗ Site sem plugin vira beco sem saída
  • ✗ Tarefa repetida toda semana, do mesmo jeito

✓ Com o navegador

  • ✓ Ele mesmo abre o site e busca a informação
  • ✓ Os dados chegam direto na pasta do projeto
  • ✓ Funciona em sites que não têm integração
  • ✓ Você assiste e pode interromper a qualquer momento
2

Faça login uma vez e reutilize

O navegador do Codex guarda a sessão, como o seu navegador de sempre. Você entra no site uma vez, com seu usuário e senha, e nas próximas tarefas ele já encontra a porta aberta.

O ponto importante: quem digita a senha é você, não o agente. Você não cola senha na conversa nem guarda senha em arquivo da pasta. Faz o login com as próprias mãos na aba do navegador e depois devolve o controle.

Como ler o desenho: o quadro âmbar é o único momento em que a senha aparece, e quem digita é você. A chave azul no meio é a sessão salva. Nos dias seguintes o agente só usa a chave.

1

Abra a aba do navegador no Codex

Dentro do projeto certo (o Rui usa loja-rui), abra o navegador embutido e digite o endereço do site.

2

Faça o login você mesmo

Digite usuário, senha e, se o site pedir, o código do celular. O agente não precisa ver nada disso.

3

Confirme que entrou

Veja seu nome no canto da página. Se a sessão está aberta, o Codex também está.

4

Faça o pedido na conversa

Agora escreva o que quer. Nas próximas vezes, pule direto para este passo.

💡 Sessão salva é a chave da sua casa

Uma sessão aberta dá ao agente o mesmo acesso que você tem naquele site. Faça login só nos sites que ele realmente vai usar e, quando acabar um trabalho pontual, saia da conta (o botão "Sair" do próprio site).

3

Peça uma tarefa num site sem integração

O pedido é igual a qualquer outro: diga o site, o que buscar e onde guardar. A diferença é que você também diz o que ele não pode fazer, porque ali ele está mexendo numa conta real.

A Paula participa de uma comunidade de RH que não tem integração nenhuma. Toda segunda ela entrava, lia as discussões da semana e anotava as dúvidas mais repetidas para virar post. Agora o Codex faz a coleta, e ela só escreve.

Como ler o desenho: as caixas azuis são o trabalho dentro do site; a âmbar é o resultado na pasta. A faixa vermelha embaixo é a cerca: enquanto estiver no site, ele só lê.

4

Entenda como o agente enxerga a tela

O agente não "sente" o site. Ele tira uma espécie de foto da tela, olha a imagem, decide onde clicar ou o que digitar, age e tira outra foto para ver o que mudou. É o mesmo ciclo do módulo 1.3 (pensar, agir, responder), só que a ferramenta agora é o mouse e o teclado.

Com o modelo mais forte, isso funciona muito bem: ele lê tabelas, acha botões escondidos em menus e consegue até reproduzir um desenho num editor online a partir de uma foto. Com modelos menores, erra mais o lugar do clique.

Como ler o desenho: à esquerda, a tela com as marcações tracejadas que o modelo "enxerga": ele reconhece um campo e um botão. À direita, o ciclo que se repete a cada passo. Cada volta custa tempo e cota, por isso o navegador é mais lento que um plugin.

✓ Onde ele vai bem

  • ✓ Páginas com textos, tabelas e listas claras
  • ✓ Formulários simples, com rótulos visíveis
  • ✓ Menus e filtros padrão (data, categoria)
  • ✓ Copiar dados de várias páginas para um arquivo

✗ Onde ele tropeça

  • ✗ Testes "não sou um robô" (ele para e chama você)
  • ✗ Telas que mudam a cada segundo, como animações
  • ✗ Sites que trocam de layout sem aviso
  • ✗ Botões só com ícone, sem texto nem descrição
5

Escolha entre plugin, API e navegador

Existem três jeitos de o Codex conversar com um serviço da internet. Eles formam uma escada: comece pelo degrau de cima e só desça quando o de cima não existir.

O plugin (módulo 3.6) é a porta oficial e pronta. A API ou o MCP são portas oficiais que exigem uma configuração (no terminal, codex mcp list mostra as conexões MCP que você já tem). O navegador é entrar pela porta da frente, como uma pessoa: funciona em quase tudo, mas é o mais lento e o que mais quebra quando o site muda.

Como ler o desenho: cada degrau abaixo é mais universal e mais frágil. As setas tracejadas mostram quando descer: só quando o degrau de cima não existe para aquele serviço. A seta à direita lembra o preço de descer.

CaminhoVelocidadeQuebra quando…Exemplo
PluginAltaQuase nuncaPaula lendo a agenda conectada
API / MCPAltaA chave vence ou muda a versãoRui consultando o sistema de notas
NavegadorBaixaO site muda um botão de lugarRui no portal do fornecedor

O que olhar na tabela: a coluna "Quebra quando…". Uma tarefa semanal pelo navegador precisa ser conferida de vez em quando, porque um dia o site muda e ela para.

💡 Pergunte antes de escolher

Não sabe se existe plugin? Peça: "Para trabalhar com <nome do site>, existe plugin, API ou MCP? Se não existir, use o navegador." O Codex procura primeiro e só desce a escada se precisar.

6

Use o navegador com regras

No navegador, o agente age em seu nome, com a sua conta. Um clique errado num arquivo da pasta se desfaz; um "Confirmar compra" num site, não. Por isso o navegador pede regras mais firmes que o resto.

O Rui escreveu as regras no AGENTS.md da loja-rui, assim vale para toda conversa. E usa o modo de permissão Pedir aprovação (módulo 3.3) sempre que a tarefa envolve um site onde dá para gastar dinheiro.

Como ler o desenho: cada cor do semáforo é uma faixa de ações. O verde ele faz direto; no amarelo ele monta e espera seu "ok"; no vermelho ele para e entrega o controle para você clicar.

✓ Regras que funcionam

  • ✓ "No navegador, só leitura, a menos que eu diga"
  • ✓ "Pagamento, compra e envio: pare e me chame"
  • ✓ Um site por tarefa, com o endereço escrito
  • ✓ Salvar o resultado num arquivo para conferir

✗ Armadilhas

  • ✗ Deixar logado no banco "para facilitar"
  • ✗ Usar Acesso total em tarefa com site de compras
  • ✗ Colar senha na conversa
  • ✗ Pedidos vagos como "resolva lá no site"
